    What the library actually uses

    The formulas do nearly all their work inside Clothes, which is where counting is annoying and where over-packing happens.

    RuleApplied toReasoning

    Where a formula is set

    Formulas live in the library. Trips hold numbers.

    SurfaceWhat you set
    Settings → Item Library → item → Default Quantitythe rule
    Sections & Kits Library → Browse Kits → kit → itema per-kit override of the rule
    A row on a tripa number, for that trip only

    There is deliberately no formula picker inside a trip. By the time the trip exists the math has happened; what you want then is "make it four."

    A per-kit override lives on the kit and doesn't leak — the same item can be ×1 in one kit and ×2 in another. Overridden entries display as "Customized for [kit name]".

    Recomputation — the part that changed

    At trip creation: every formula-driven quantity is computed against the trip's dates and stored on the trip.

    When you change the trip's dates: formula-driven quantities are recomputed, after confirmation. This shipped 2026-09-18.

    Three categories are never touched:

    1. Hand-set quantities. Anything you typed, or anything on an Always Custom rule.
    2. Rows you added yourself.
    3. Rows the same change is removing — a date edit also changes which items belong.

    The confirmation flow: the alert counts, the review sheet names. A real date edit produced twenty-two quantity changes in testing, and an alert that tried to list them spent three lines naming four. So the alert says how many; Review Updates shows which.

    Names read at the quantity they're moving to — a row going 1 → 3 reads "T-shirts", not "T-shirt".

    Why this changed

    Before it, the two halves of a date edit disagreed. Stretching a weekend into two weeks added the longer trip's items and left every quantity at the weekend's figure — silently. That's an under-pack, which is the specific failure the app exists to prevent.

    Templates and length

    A template carries a nominal length in nights. When you create a trip from it, quantities compute against your trip's dates, not the template's — so one template gives three shirts for a weekend and seven for two weeks.

    The template's own number matters only when nothing else is available to count against.

    ⚠️ The nominal length does a second, less obvious thing. At authoring time it becomes a trip duration category, which filters which library items seed into the template at all. A 3-night template and a 10-night template come out with genuinely different contents. The default is 3 nights, chosen silently.
